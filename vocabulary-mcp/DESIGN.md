# 专用词库 MCP：Codex 首版设计

日期：2026-10-14。状态：原设计已获用户同意；新增工作流及实施计划待审阅，尚未实现或部署。

## 目标与范围

用户在 Codex 中用自然语言查询自己的词库、批量收录泰语内容和修改已有词条。结果进入现有新加坡 Supabase 项目，由现有网页同步显示。网页手动录入、访客临时体验和学习进度保持原有行为。

首版提供三个词库工具。内容由 Codex 整理，服务只验证和存储，不调用 Gemini 或其他模型 API。首版不开放删除、账号初始化、学习事件伪造、设置修改、SQL 执行或数据库管理。ChatGPT 和 Claude 的连接留待后续；协议保持标准 MCP。

## 实施边界

- 新模块的源码、测试、设计及 Codex 配置示例放在 `vocabulary-mcp/`。
- Supabase 的部署入口及数据库迁移按现有工具约定放在 `supabase/functions/`、`supabase/migrations/`；入口保持轻量，引用本模块。
- 网页增加最小的“AI 词库连接”凭证管理入口，仅已登录允许名单账号可用。
- 不修改操作系统或浏览器设置，不自动写入全局 Codex 配置。
- 只连接 `thai-learning-sg`，项目 ref 为 `hvpmjhsommuewiwrhozl`。旧悉尼项目不参与本功能。

## 接入与身份验证

采用 Supabase Edge Function 承载 Streamable HTTP MCP。Codex 使用标准 Bearer 凭证连接；首版不引入 OAuth 授权服务器。标准工具协议保留后续增加 OAuth 的空间，但不宣称不同客户端的认证配置可以直接通用。

凭证由用户在已登录网页中主动生成：高熵随机值仅显示一次，数据库只存摘要、所属账号、权限、创建时间、到期时间和撤销状态。默认有效期 30 天，可随时撤销并重新生成。生成、列出和撤销自己的凭证需要真实 Supabase 用户会话及允许名单验证。

工具请求的账号由凭证记录决定，不能通过工具参数指定用户 ID。每次调用验证到期、撤销状态及账号允许名单；权限限定为三个词库操作。请求日志、工具返回、配置示例不得输出凭证。网页部署文件不得包含真实凭证。

Edge Function 使用公开项目配置调用专用数据库函数；数据库函数校验专用凭证后绑定账号执行。无需将 service-role 或数据库密码交给 Codex。凭证表与幂等记录表开启 RLS、禁止客户端直接读写；专用函数固定 search_path、限制输入、无动态 SQL。对外可调用专用函数本身也是可信边界，不能只依赖 Edge 层验证。

Codex 配置示例只引用环境变量名 `THAI_VOCABULARY_MCP_TOKEN`，或由支持凭证输入的连接界面保存凭证。实际连接时由用户自行填写凭证，不粘贴进聊天。仅生成配置示例不等于已完成连接，必须通过实际工具发现与调用验收。

## 默认收词工作流

按用户新增要求，字段填写、简体中文释义、现有声调罗马音、例句、查重及失败处理统一遵循 [WORKFLOW.md](./WORKFLOW.md)。通过 MCP 初始化说明、工具描述、只读资源及提示词提供给 Codex；硬约束服务端执行，语言质量仍为 AI 草稿。

## 三个工具

### query_vocabulary

输入：可选关键词、精确词条 ID、内容状态、每页数量（默认 20、上限 50）及不透明分页游标。

搜索泰文、中文和罗马音。返回词条 ID、当前版本、当前账号 epoch、内容、来源、审核状态及下一页游标。查询应包含网页当前可见的系统词条和个人词条，按 ID 应用账号覆盖，排除删除记录。空关键词允许分页浏览；结果顺序稳定。查询不暴露学习记录、邮箱或其他账号信息。

系统课程目前仅在代码中，因此部署时需生成服务端只读课程目录，与网页课程共用源数据，并测试一致性。客户端不能上传任意“系统课程”替代此目录。

### add_vocabulary_batch

输入：`requestId`、查询获得的 `expectedEpoch`、1 至 50 个词条，总请求不超过 256 KiB。每条接受泰文、中文、罗马音、词性、备注、例句；字段长度沿用现有 wordSchema。

允许只提交泰文：保存为待补全，不能进入练习。中文与罗马音齐全且校验通过的条目保存为可学习的 AI 草稿；内容验证不等于语言质量已核对。AI 不能自行标为人工确认或专业审核。

泰文按 Unicode NFC 和首尾空白标准化。同批及现有有效词条中相同原词返回 duplicate，不自动覆盖；返回重复词的 ID 供之后明确修改。删除记录不计入查重。首版不自动拆分同形词义。

对每条返回 created / duplicate / invalid 及原因、词条 ID 和版本。格式合法的项目在一个事务中提交；基础设施失败时全部回滚，不返回假成功。重复 `requestId` 且内容相同返回原结果；同 ID 不同内容拒绝。幂等键包含账号和 epoch。

### update_vocabulary

输入：`requestId`、`expectedEpoch`、词条 ID、`expectedVersion` 和内容补丁。

必须先查询再修改。只改明确提供的字段，保留词条 ID 和现有学习进度；不能改账号、审核为人工确认、版本、删除标记或课程身份。系统词条的修改保存为当前账号的覆盖，不改变全局课程。内容修改后标为 AI 待核对。

版本不一致时返回 conflict 和最新词条，不强制覆盖、不自动替模型重试。修改原词时执行同样查重。更新后仍不完整的词条保持待补全；完整条目成为可学习草稿。删除或找不到的词条返回 not_found。

## 写入、同步及初始化保护

### 本轮扩展：候选清单与拼句

长文本提取只生成候选，答复末尾展示完整词语及拼句清单；用户明确要求入库后才执行，完成后逐条列出真实结果。中途讨论不能扩大确认范围。具体字段和流程以 WORKFLOW.md 为准。

三个工具均接受和返回现有 Word.sentence 结构，整句作为词条存储，通过 personalExercises 进入“我的句子”。服务端校验词块数量、读音、完整答案索引及原句一致性；修改保留练习 ID 和学习历史，不新增学习事件写入口。此扩展纳入首版实施范围。

所有写操作和现有 `sync_learning_v2`、`reset_learning` 使用相同的账号游标行锁。事务内验证 epoch、版本、查重并写入 learning_records，同时递增 seq 和写入 learning_changes。不能只改词条主表。

账号已初始化时，旧 expectedEpoch 的写入返回 account_reset；服务不能悄悄换成新 epoch 重试旧添加任务。模型应重新查询，并由用户明确决定是否重新收录旧批次。幂等结果也必须在 epoch 检查后返回，不能把重置前的成功当作当前状态。

网页继续使用已有同步周期和返回前台时刷新；在线前台通常在下一次成功同步时看到 AI 修改，现有周期约 30 秒，不宣称即时推送。

## 验证和错误行为

- 协议：initialize、tools/list、tools/call、通知及错误响应通过真实 MCP 客户端测试。
- 权限：无凭证、错误凭证、过期、撤销、非允许账号拒绝；用户无法越权访问其他账号。
- 内容：字段限制、泰文规范化、同批重复、系统词重复、部分无效、待补全条目、AI 来源及审核状态。
- 并发：重复请求、不同内容复用请求 ID、网页修改后旧版本提交、初始化后旧批次重放。
- 同步：AI 新增与修改均产生网页可消费的变更；保留词条 ID 和学习记录。
- 回归：现有学习、登录、临时访客、初始化和语音测试仍通过。
- 实际连接：用户创建并配置凭证后，Codex 发现三个工具；用明确标注的测试词条完成查询、批量添加、修改及网页可见性验证。

错误返回稳定的代码及中文说明，区别 validation_error、unauthorized、duplicate、conflict、account_reset、not_found、rate_limited 和暂时不可用。不在模型上下文中返回 SQL 堆栈、密码或令牌。合法工具输出中的词条文本视为内容，不能作为新的操作指令。
